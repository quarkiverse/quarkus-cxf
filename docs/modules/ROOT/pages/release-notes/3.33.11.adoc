== Enhancements

=== New WS-Addressing decoupled endpoint configuration options

The following options configure the WS-Addressing changes introduced in
https://github.com/apache/cxf/pull/3279[Apache CXF PR #3279]:

* `xref:reference/extensions/quarkus-cxf.adoc#quarkus-cxf_quarkus-cxf-endpoint-addressing-decoupled-enabled[quarkus.cxf.endpoint.addressing.decoupled.enabled]` -
  enables non-anonymous `wsa:ReplyTo` and `wsa:FaultTo` destinations requested by clients. Defaults to `false`.
* `xref:reference/extensions/quarkus-cxf.adoc#quarkus-cxf_quarkus-cxf-endpoint-addressing-decoupled-allowed-schemes[quarkus.cxf.endpoint.addressing.decoupled.allowed-schemes]` -
  controls the permitted URI scheme prefixes. Defaults to `http://` and `https://`.

These options replace the plain CXF system properties `org.apache.cxf.ws.addressing.decoupled.enabled`
and `org.apache.cxf.ws.addressing.decoupled.allowedSchemes`.
Setting either system property directly causes the application to fail at startup.
WS-Addressing log and error messages now refer to the corresponding {quarkus-cxf-project-name} configuration options.

== Breaking changes

=== WS-Addressing decoupled destinations disabled by default

Before {quarkus-cxf-project-name} 3.39.0 and 3.33.11, WS-Addressing clients could request non-anonymous reply or fault destinations
without explicitly enabling this on the server.
Since {quarkus-cxf-project-name} 3.33.11, such requests are rejected with a `DestinationUnreachable` fault by default
to prevent Server-Side Request Forgery (SSRF).
Applications that require decoupled WS-Addressing callbacks must enable them using
`xref:reference/extensions/quarkus-cxf.adoc#quarkus-cxf_quarkus-cxf-endpoint-addressing-decoupled-enabled[quarkus.cxf.endpoint.addressing.decoupled.enabled]`
and configure the allowed URI scheme prefixes via `xref:reference/extensions/quarkus-cxf.adoc#quarkus-cxf_quarkus-cxf-endpoint-addressing-decoupled-allowed-schemes[quarkus.cxf.endpoint.addressing.decoupled.allowed-schemes]` if the defaults are insufficient.

=== Default attachment size limit

Before {quarkus-cxf-project-name} 3.39.0 and 3.33.11, CXF did not impose a default maximum attachment size.
Since {quarkus-cxf-project-name} 3.33.11, the upgrade to CXF 4.1.8 introduces a default limit of 50 MB.
Applications that process larger attachments must explicitly configure the CXF `attachment-max-size` contextual property.
See https://cxf.apache.org/docs/securing-cxf-services.html#SecuringCXFServices-Multiparts[Securing CXF Services] for details.

=== Apache HttpComponents dependency management

The {quarkus-cxf-project-name} BOM no longer manages Apache HttpClient 5 and HttpCore 5 artifacts directly.
Their versions are now managed by the Quarkus BOM.
Applications relying solely on the {quarkus-cxf-project-name} BOM for these artifacts should use the
xref:user-guide/create-project.adoc#quarkus-platform[Quarkus Platform BOMs] or provide their own dependency management.
