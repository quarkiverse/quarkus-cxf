[[advanced-service-topics]]
= Publish and configure SOAP services

Decide where your SOAP services are published and how they are implemented: set endpoint paths, process raw XML with JAX-WS providers, serve REST and SOAP endpoints from one application, and advertise the right addresses when a service runs behind a reverse proxy.

== Where to go

* xref:user-guide/advanced-service-topics/endpoints-and-paths.adoc[Endpoints and paths] - Set them by property or by annotation, including the `@CXFEndpoint` producer-method form that returns a mock implementation for client tests. A service is published under a path either with the `xref:reference/extensions/quarkus-cxf.adoc#quarkus-cxf_quarkus-cxf-endpoint-endpoint-path-implementor[quarkus.cxf.endpoint."/endpoint-path".implementor]` property or with the `@CXFEndpoint` annotation, whose value is relative to `xref:reference/extensions/quarkus-cxf.adoc#quarkus-cxf_quarkus-cxf-path[quarkus.cxf.path]`; the two are equivalent, and other properties set for that path apply either way.
* xref:user-guide/advanced-service-topics/jax-ws-providers.adoc[JAX-WS Providers] - Implement one when the service must handle the raw XML payload instead of Java method parameters. A JAX-WS `Provider<T>` implementation registers through the same `implementor` property as a regular `@WebService` class.
* xref:user-guide/advanced-service-topics/rest-and-soap-endpoints.adoc[REST and SOAP Endpoints] - Separate them by root path when one application has to expose both. REST and SOAP endpoints share one application when each stack has its own root path, such as `quarkus.cxf.path=/soap` next to `quarkus.resteasy.path=/rest`.
* xref:user-guide/advanced-service-topics/running-behind-a-reverse-proxy.adoc[Running behind a reverse proxy] - Enable proxy address forwarding only when a real reverse proxy sits in front of the service, because it exposes the server to spoofed request information. Behind a reverse proxy, `{link-quarkus-docs-base}/all-config#quarkus-vertx-http_quarkus-http-proxy-proxy-address-forwarding[quarkus.http.proxy.proxy-address-forwarding]` and the related `quarkus.http.proxy.*` settings make Quarkus honor the `X-Forwarded-*` headers, so the address advertised in the served WSDL is the public one.
