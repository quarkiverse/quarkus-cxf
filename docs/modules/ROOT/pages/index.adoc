[[quarkus-cxf-index]]
= {quarkus-cxf-project-name}

Keep the SOAP contracts your applications and partners rely on while you move those applications to Quarkus: {quarkus-cxf-project-name} brings http://cxf.apache.org/[Apache CXF] and the JAX-WS programming model to the Quarkus runtime, with full support for GraalVM native images.

Instead of rewriting a working SOAP integration as REST, or leaving it on an application server you no longer want to run, you carry the existing WSDL contract and JAX-WS code into a Quarkus application that starts fast and compiles to a https://quarkus.io/container-first/[GraalVM native image].

[IMPORTANT]
====
While http://cxf.apache.org/[Apache CXF] implements wide range of standards and specifications,
{quarkus-cxf-project-name} is currently focusing *only* on supporting the ones related to
*Simple Object Access Protocol* (https://en.wikipedia.org/wiki/SOAP[SOAP])
and *Java API for XML Web Services* (https://en.wikipedia.org/wiki/JAX-WS[JAX-WS]).
Refer to xref:reference/index.adoc[Reference] to learn which parts of CXF are supported.
====

== What you get

* *JAX-WS services and clients.* Your existing WSDL contracts and JAX-WS code carry over.
* *Contract-first and code-first development.* `wsdl2java` and `java2ws` run inside the Quarkus Maven plugin, so a changed WSDL is picked up by the normal build rather than by a separate tool step.
* *The standards enterprise contracts commonly require.* WS-Security, WS-SecurityPolicy, WS-ReliableMessaging, and WS-Trust, through companion extensions.
* *Production insight.* Micrometer metrics and OpenTelemetry tracing for your services and clients.
